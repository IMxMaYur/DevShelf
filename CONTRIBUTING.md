# 🤝 Contributing to DevShelf

Thank you for your interest in contributing to DevShelf!

DevShelf is a community-driven collection of useful resources for students, beginners, and developers.

Our goal is simple:

> **Make it easier for people to discover useful, reliable, and practical developer resources.**

We welcome contributions that improve the quality, usefulness, and organization of the project.

---

## 📚 What can you contribute?

You can contribute:

- 🚀 Projects
- 🔌 APIs
- 📖 Courses
- 📄 Documentation
- 🔬 Research papers
- 📊 Datasets
- 🛠️ Developer tools
- 🤖 AI/ML resources
- 📱 Mobile development resources
- 🎓 College resources
- 💼 Career resources
- 📋 Templates
- 🧹 Documentation improvements
- 🔗 Broken-link fixes
- 💡 Suggestions for improving DevShelf

---

## ✅ Before submitting a resource

Please make sure the resource:

- Is relevant to developers, students, or learners.
- Has a clear purpose or use case.
- Is publicly accessible.
- Has a working URL.
- Is placed in the correct category.
- Is not an obvious duplicate.
- Has accurate information.
- Respects its original license and copyright.
- Does not contain malicious or suspicious content.
- Does not promote piracy or illegal activity.

---

## ⭐ Resource Quality

DevShelf prioritizes **quality over quantity**.

Before submitting a resource, ask:

1. Is this actually useful?
2. Would another developer benefit from it?
3. Is the source legitimate?
4. Is the description accurate?
5. Is the resource still maintained or accessible?
6. Is the license clear where applicable?
7. Is there already a similar resource in DevShelf?

If the answer to most of these questions is yes, it is probably a good candidate.

---

## 🏷️ Resource Information

When possible, include useful metadata such as:

- Name
- Description
- Category
- Difficulty
- Technology
- Programming language
- Framework
- License
- Source URL
- Demo URL
- Documentation URL
- Free / paid status
- Verification status
- Last verified date

Do not guess information.

If you cannot verify something, leave it out or clearly mark it as unknown.

---

## 🔎 Avoid Duplicate Resources

Before submitting a resource:

1. Search DevShelf.
2. Check the relevant category.
3. Search for the project/resource name.
4. Check whether the same URL already exists.

If a similar resource already exists but yours provides a significant advantage, explain the difference in your pull request.

---

## 🔗 Links

Prefer linking directly to the original source.

Examples:

- Official documentation
- Original GitHub repository
- Official project website
- Official research paper
- Official dataset source
- Official course page

Avoid unnecessary link shorteners.

---

## 🛡️ Security

Do not intentionally submit:

- Malware
- Credential stealers
- Malicious scripts
- Phishing websites
- Suspicious downloads
- Pirated software
- Cracked applications
- Stolen content
- Unauthorized copyrighted material

If you discover a potentially malicious resource already listed in DevShelf, report it immediately through an issue.
